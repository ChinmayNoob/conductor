Frequently asked questions

Is delivery exactly once?
No, and no system that runs arbitrary side effects can promise that honestly. Delivery is at least once: a task whose worker dies is run again. What Conductor does guarantee is that only one result is recorded per task (attempt fencing), that a deposed leader changes nothing (epoch fencing), and that you get the tools to make effects idempotent: a stable CONDUCTOR_TASK_ID, a per-dispatch CONDUCTOR_ATTEMPT, and idempotency keys on submission. See delivery guarantees.
Do I need Kubernetes?
No. One binary and Postgres are enough (conductor dev, or one process per component), and Docker Compose runs a highly available stack on one host. Kubernetes adds autoscaling, tasks as pods and GitOps.
Which languages can I use?
Any. Tasks are shell commands, HTTP calls, containers or pods, so your code is whatever those run. Clients use the HTTP API; a Go SDK (pkg/client) and the conductorctl CLI are included.
How fast is it?
On a laptop with everything in one Docker VM: about 800 no-op tasks per second drained, around 1,000 submissions per second, about 5 ms from submit to dispatch when idle, and under 10 ms dispatch (p50) at 200 tasks per second. Postgres is the limit; see scaling.
What happens if Postgres goes down?
Nothing is dispatched or recorded while it is down. Running tasks keep running, and workers retry reporting their results for up to 30 seconds per report. When Postgres returns, coordinators reconnect and re-elect a leader, and anything whose result was lost is recovered as lost and retried. The chaos suite restarts Postgres under load and checks that nothing is lost.
Can a workflow branch on a condition, or loop?
Not today: a workflow is a DAG, and every step runs once its dependencies complete. A step can decide to do nothing (exit 0) based on an earlier step's output, and an agent step loops by design. Conditional steps are a candidate for a future release.
How long can a task run?
As long as its timeout allows. For long tasks, size the workers' shutdown timeout to them, or accept that a deploy or scale-down retries them elsewhere; make them resumable if that matters.
Can teams share one installation?
Yes: namespaces separate tasks, definitions, runs, schedules, queues and keys, with quotas per namespace. Admin keys span them all.
Where does output go?
Into Postgres, on the task (1 MB by default, keeping the beginning and the end). Previous attempts keep theirs. Keep large artefacts in object storage and pass references through outputs.
Is the name final?
No. "Conductor" is already a well-known workflow engine (Netflix Conductor, now Conductor OSS), so the project will be renamed before its open-source launch; the module path, images and docs will follow.
What is the licence?
Apache 2.0.

Known limits

  • Workflows are DAGs: no conditional steps or loops (agents excepted).
  • Throughput is bounded by one Postgres; the leader does the dispatching, so scaling past a few hundred tasks per second needs a stronger database, not more coordinators.
  • Container images are not published yet; build them from the repository.
  • The assistant's own model spend doesn't count against namespace budgets, and identical prompts aren't cached.
  • Kubernetes tasks run as bare pods (one per attempt), not Jobs; their outputs are limited to 4 KB.
  • The chart's NetworkPolicies restrict ingress only.
