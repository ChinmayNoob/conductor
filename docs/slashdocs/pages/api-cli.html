Authentication and conventions

  • Every /v1 route needs Authorization: Bearer <api key>. Keys are created with conductorctl apikey create; the first admin key comes from CONDUCTOR_API_KEY on startup.
  • A key acts in its own namespace. Admin keys may act in another by sending X-Conductor-Namespace: NAME.
  • Bodies are JSON (workflow definitions may also be YAML). Errors are {"error": "message"} with a meaningful status: 400 invalid, 401 no or bad key, 403 not allowed, 404 not found, 409 conflict (already finished, already exists), 429 over a quota or budget.
  • Creating something returns 201; an idempotent repeat (same idempotency key, unchanged definition, existing schedule on PUT) returns 200.
  • The API is versioned under /v1. GET /health needs no key and reports whether the API can reach its database.
export CONDUCTOR_URL=http://localhost:8081 CONDUCTOR_API_KEY=cnd_...
curl -s -H "Authorization: Bearer $CONDUCTOR_API_KEY" \
     -d '{"command": "echo hi", "priority": 2}' $CONDUCTOR_URL/v1/tasks

conductorctl

The command-line client covers the whole API. Global flags: -url (or CONDUCTOR_URL, default http://localhost:8081), -api-key (or CONDUCTOR_API_KEY), -n NAMESPACE for admin keys, and -o json for machine-readable output.

Go SDK

The pkg/client package wraps the whole API with typed requests and responses. It is what conductorctl and the Kubernetes operator use.

import "github.com/ChinmayNoob/conductor/pkg/client"

c := client.New("http://localhost:8081", os.Getenv("CONDUCTOR_API_KEY"))

// A task, waited for.
task, err := c.SubmitTask(ctx, client.TaskRequest{Command: "make report", Queue: "reports", MaxRetries: client.Retries(5)})
task, err = c.WaitForTask(ctx, task.ID)

// A workflow run, once per order however often this code runs.
wf, err := c.StartWorkflow(ctx, client.WorkflowRequest{
    Workflow: "order_pipeline", Input: map[string]any{"order_id": "A1"}, IdempotencyKey: "order-A1",
})
wf, err = c.WaitForWorkflow(ctx, wf.ID)
fmt.Println(wf.Status, wf.Step("charge_card").Outputs["charge"])

// Another namespace (admin keys).
teamA := c.WithNamespace("team-a")

Errors from the API are *client.APIError values with the status code; client.IsNotFound(err) and client.StatusCode(err) test them. Other methods cover definitions (ApplyDefinition), approvals and signals (ApproveStep, Signal), schedules (CreateSchedule, PutSchedule), queues, workers, namespaces and API keys.

The dashboard

The API serves a web dashboard at /ui/ (/ redirects there), built into the binary. Sign in with an API key; it acts with that key's permissions, and admin keys can switch namespaces. Pages:

  • Overview: waiting and running work, the last hour's outcomes, queues, recent failures, active runs.
  • Tasks and a task's page: search and filter, every attempt, live output, outputs, the assistant's explanation of a failure.
  • Workflow runs: a live diagram of the run; the failed step, why, and what was compensated, in one banner; approvals and signals; agent conversations and model spend.
  • Approvals, workers, schedules, queues, the dead-letter queue, and an assistant page for questions and drafted workflows.

Actions: cancel tasks and runs, requeue from the dead-letter queue, pause or resume queues and schedules, run a schedule now, approve or reject, send a signal.
